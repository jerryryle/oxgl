# Spec Delta

## Purpose

Defines the WebGL error model in oxgl: how GL errors are recorded and reported through `getError`, how lost or destroyed contexts report errors, and how internal failures surface without crashing the host process.

## ADDED Requirements

### Requirement: getError semantics
`getError()` SHALL behave as specified in WebGL 1.0 §5.14.3 "Setting and getting state" and OpenGL ES 2.0 §2.5: it returns and clears one recorded error, returning `NO_ERROR` when none is recorded. Errors generated by oxgl's own WebGL-level validation and errors generated by the underlying GL implementation SHALL be reported through the same flag set, indistinguishably.

#### Scenario: No error initially
- **WHEN** `getError()` is called on a new context
- **THEN** it returns `NO_ERROR`

#### Scenario: Error is reported once
- **WHEN** `clear(0x1)` is called, then `getError()` twice
- **THEN** the first call returns `INVALID_VALUE` and the second returns `NO_ERROR`

#### Scenario: Validation and GL errors share flags
- **WHEN** one call fails oxgl-level validation with `INVALID_OPERATION` and a later call generates `INVALID_VALUE` in the GL layer
- **THEN** repeated `getError()` calls return both errors, one per call, then `NO_ERROR`

### Requirement: Lost-context error reporting
While a context's webgl context lost flag is set, `getError()` SHALL return `CONTEXT_LOST_WEBGL` the first time it is called and `NO_ERROR` afterward (WebGL 1.0 §5.14.3), and other methods SHALL follow the `[WebGLHandlesContextLoss]` rules of WebGL 1.0 §5.14 without generating errors.

#### Scenario: Lost context
- **WHEN** a context is destroyed and `getError()` is called three times
- **THEN** it returns `CONTEXT_LOST_WEBGL`, `NO_ERROR`, `NO_ERROR`

### Requirement: Internal failures do not crash the process
Failures inside oxgl or the backend that the WebGL specification does not model as GL errors SHALL NOT terminate the Node process. A failure that leaves the context unusable SHALL put it into the lost state; a failure the WebGL IDL treats as an exception SHALL throw a JS exception.

#### Scenario: Backend device loss
- **WHEN** the backend reports that the underlying device or context was lost during a call
- **THEN** the call returns normally, the context enters the lost state, and the next `getError()` returns `CONTEXT_LOST_WEBGL`

### Requirement: Error constants
The context instances and their constructors SHALL expose, with WebGL IDL values, `NO_ERROR`, `INVALID_ENUM`, `INVALID_VALUE`, `INVALID_OPERATION`, `INVALID_FRAMEBUFFER_OPERATION`, `OUT_OF_MEMORY`, and `CONTEXT_LOST_WEBGL`.

#### Scenario: Constant values
- **WHEN** `gl.INVALID_VALUE` and `gl.CONTEXT_LOST_WEBGL` are read
- **THEN** they equal `0x0501` and `0x9242`
